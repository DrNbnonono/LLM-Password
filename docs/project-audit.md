# 项目完整性检查（2026-10-23）

结论：现有目录包含可用的研究代码主体，不能称为已经完成长期监测与完整复现的项目。

- 共 32 个现有 Python 文件：src 下 9 个、scripts 下 23 个。API 采集、提示构建、CSV 记录、熵估算、zxcvbn 评分、分布分析、特征工程和分类训练均有实现。
- API 客户端仅实现 OpenRouter 和 SiliconFlow。env.example 中其他供应商配置不表示已接入。
- README 原来描述为项目书存档，和实际代码不符；发布包 README 按代码现状重新整理。
- requirements.txt 只覆盖采集，分析脚本还需要 pandas/numpy/scipy/sklearn/绘图等依赖。requirements-analysis.txt 补充该清单，TensorFlow 需按平台单独安装。
- 原 pyproject.toml 的 src 布局发现方式和 `from src...` 导入方式不一致。本次发布包使用项目根目录运行 `python -m src.cli.generate`；未宣称可通过 pip 安装为完整 CLI。
- 采集按固定请求次数运行，无调度、预算上限、告警、跨进程锁、监控服务和失败任务补采。单次请求有重试，但不足以构成长期监测系统。
- CSV 有模型、提示、温度和 UTC 时间戳，但不保留原始响应、拒绝状态、请求 ID、供应商报告的模型版本和 token 用量。只提取第一条非空文本，模型解释或拒绝可能被当成口令。
- 采集过程计算 zxcvbn 分数但未写入 CSV；Crack_Time 的键带了不匹配的 `_display` 后缀，可能一直得到 unknown。长于 72 字符直接被当成强口令，会影响研究结论。
- Pattern_Score 固定为 0，熵只是字符空间估算，不能作为真实密码熵。部分失败会被捕获后继续，进程仍可能成功退出，长期调度需额外检查有效样本数。
- 分析/训练脚本依赖 data 下既有数据，分类预测依赖训练产物；代码包不包含这些文件，因此不能直接复现历史图表或分类准确率。

本次验证：现有 Python 文件语法解析；新隧道参数测试与 PowerShell 解析；实际 SSH 反向代理连通；服务器包装器语法、Codex 版本与登录状态检查。不调用研究 API，不复跑训练或历史结果。完整性判断来自静态检查与局部运行验证，不能视作所有脚本通过端到端测试。

后续长期监测应优先补：原始输出与错误分型、zxcvbn 数值分数、模型版本和调用参数、每批成功/失败数量、周期调度与互斥、限额与告警、时间序列汇总。在这些完成之前不要把现有数据采集器视为可靠的无人值守服务。
